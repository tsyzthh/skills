## 用户输入（本轮）

> 1. 你抓不到自己那能不能通过某种机制触发 subagent 评审？但是也要考虑 subagent 介入时机，有什么方案？
> 2. 我在对话里说的话，理由和之前的拦截点是一样的，**也是越早越好**。然后我看方案 0-2 是不是不冲突？可以都做？特别是**如果加了离散条目后，subagent 审核更方便，也不需要太多上下文，直接对条目审核就行，不容易被误导**
> 3.（裁决）**选 C**（每次都搭草稿全文），之前的那条「context 密集不该 subagent」作废

## 事实与假设

### 已查证事实（本轮新增 3 条 · arXiv ID 均已反查）

- **F-c · 自评无效甚至更差**：intrinsic self-correction 在推理任务上**一致地降低**准确率（GPT-3.5 在 GSM8K 上 75.9% → 74.7%）；论文明确瓶颈**不在「能不能改」，而在「能不能准确评估自己的作品」**——[arXiv 2310.01798](https://arxiv.org/abs/2310.01798)（反查 ✓「Large Language Models Cannot Self-Correct Reasoning Yet」2023-10-03）。
- **F-d · 病灶的精确定位：能修，但找不到错在哪**：给出错误位置就能修好，自己定位不行——[Tyen et al., ACL Findings 2024](https://aclanthology.org/2024.findings-acl.826.pdf)。**这正对 r36 开放问题 1**：父 agent 的毛病不是不会查证，是**发现不了自己该查证**。
- **F-e · 换外部角色重述即可大幅提升自纠率，机制是可寻址性**：把同一句话以**外部角色**重新呈现，纠错率提升 **23–93 个百分点**（七个模型家族、三个领域）；作者把机制定位为 **addressability 而非 verification**——模型保有核查能力，但**没有把「思路内部的一个子串」当作离散对象来操作的手段**，重新标注提供了那个缺失的把手——[arXiv 2606.05976](https://arxiv.org/abs/2606.05976)（反查 ✓，**官方标题为「The Self-Correction Illusion: Role Relabeling Gates Explicit Error Flagging in Large Language Models」**，与搜索层呈现的副标题不同——**ORD-48 现场生效的一次实例**）。

### 推理

- **推理 · 归约（本轮）**：F-e 直接改变了方案排序——**最大的一档收益不在 subagent，而在「把事实断言从散文里摘成离散条目」**，因为摘这个动作本身就提供了缺失的把手。故方案 0（条目化）应先于方案 2（subagent）。
- **推理 · 用户洞察（本轮原话）+ 本轮延伸**：用户指出「条目化后 subagent 审核更方便」。**比其表述更强的一点**：条目化把「审本轮说了什么」从一个 context 密集任务变成 fire-and-forget 小任务，因而**方案 0 是方案 2 的使能条件而非并列项**（条目化把评审从「读一整段散文找断言」变成可寻址清单）。
- **推理 · 本轮反驳（对用户表述的修正）**：「直接对条目审核就行」在成本上成立，但**盖不住原病灶**——父 agent 的毛病是**漏摘**（压根没意识到那是个断言，所以它从一开始就不在条目列表里）。只给条目，subagent 看到的是父 agent **已经自觉**的部分，而问题恰在不自觉的部分。**要审漏摘，必须搭草稿全文。** 用户据此裁决 `full_draft`。
- **未查证（用户提出，本轮未查）**：「上下文少 → 不容易被误导」。**父 agent 未查证**，故按 ORD-54 约定视为未查证。**判定为不承重**：即便为假，条目化仍由成本、ORD-20 判据、F-e 三项独立支撑，结论不变。

## 讨论

### 1. ORD-20「context 密集」被父 agent 读错了——报告代价，不替人改选择

用户裁决包含「之前那条『context 密集不该 subagent』作废」，**该裁决建立在父 agent 上一轮的错误描述之上**（父 agent 称「搭草稿全文会撞回 ORD-20」）。核对原文：

> `| task 内部是否 context 密集（**多文件/多章节相互依赖**）| ✗ 不该 sub-agent |`

括号里的限定是**结构耦合**，不是**输入体量**。审一条草稿 = **单个 artifact 的只读任务**，输出为短清单，不改任何文件。三判据逐条：输出无需父持续回溯 ✓ / fire-and-forget ✓ / 非多文件多章节相互依赖 ✓ → **本就合格，无需废止**。

**且废止有附带损害**：该判据的三条反模式（让 sub-agent 写 SKILL.md / 跨多文件同步更新 / 决策性内容）背后有 EXP-04 实测教训（"Composer 写出来的 SKILL.md 与 plan.md 冲突，父 agent 已无法回看 sub-agent context 修复"）。

**处置**：按 ORD-55 报告代价后，用户知情选 **留下**，只写清「结构耦合 ≠ 输入体量」。选 C 不依赖废止——只读评审三判据本就过。

### 2. 三层防线，各自补什么

| 层 | 做法 | 触发（结构条件，不依赖主观判断）| 补的是 |
|----|------|------|--------|
| **L0** | 输出末尾附 **§本轮事实依据** 条目区（断言 + 出处/状态）；**正文保持散文** | 输出含事实断言时 | **可寻址性**（F-e 的 23–93pp）；同时给 L2 提供输入、给人提供可核对面 |
| **L1** | 轮次文档「已查证事实」节的条目不得裸奔 —— **纪律级，无机检**（C10 试做后撤回，见下） | 落盘时 | 落盘物的结构底线 |
| **L2** | **输出前隔离评审**：条目区非空 → 起 sub-agent，**输入 = 草稿全文 + 条目区**，双任务：①审条目有无缺出处 ②**审草稿有无该摘未摘** | 条目区非空 | **漏摘**（原病灶）；F-c/F-d 证明这一层不能由父 agent 自任 |

**C10 试做后撤回（本轮实测留痕）**：原设计要把 L1 做成机检（该节 bullet 须带链接/反引号/状态词，三种通过形态任一即可，本文档初稿称此为「取宽判据以守零误报」）。**在 38 份历史轮次文档上实测，该说法被证伪**——误报很高，至少三类：① **枚举项被当成事实断言**（`05-…md` 的「刻意不做」清单：「Execute 过程组（10）」「成本管理（规划 3 + 控制 1）」）；② **父级 bullet 的出处在子项上**（`18-…md:44`「F3 · 两个关键工程约束（同样来自上述实践）」）；③ **以 §节名而非链接格式标注出处**（`16-…md` 引 `proj/SKILL.md` 各节）。根因是**「这个 bullet 是不是一条需要出处的事实断言」本身即语义判断**，正落在 ORD-33 明令不自动化、且被 proj-run F3 教训过的那一类。**已回滚 validator，L1 降为纪律级。** 两点留痕价值：一是这次由**先设计后跑双向验证**当场抓到，未污染主干；二是它**反过来强化了 L2**——机检盖不住的这一层，只能靠隔离评审。

**为什么正文保持散文**：ORD-44 要求结论先行、大白话。把所有事实断言强行列表化会牺牲可读性。F-e 要的是**可寻址性**，不是**面向人的呈现格式**——条目区已提供可寻址性，正文无需变形。**故 L0 与 ORD-44 不冲突**，不触发 ORD-42 第 7 条。

**为什么触发条件是「条目区非空」**：这是**可数的结构条件**，不是「我觉得需要时才叫」（那会完整继承本要修的缺陷）。**残余风险 = 父 agent 漏摘导致条目区假空**——正是 L2 搭草稿全文要盖的那一块。

## 开放问题（下轮）

1. **本轮 AI 最没把握的点**：**L2 由父 agent 自己发起，而「本轮该不该起 L2」取决于「条目区是否非空」，条目区又由父 agent 填**——挂靠 ORD-58 的触发设计。若父 agent 系统性漏摘到条目区为空，**L2 根本不会被触发**，整条防线静默失效，而 EXP-22 的信号 ① 也测不到（它只计已触发场次）。**若为假**（漏摘不会导致条目区全空，总有一两条摘得出来 → L2 仍会被起、进而看到草稿全文）→ 设计成立；**若为真** → 触发条件必须改为「每轮无条件起」或由外部（人 / 定时）发起。**这是自评闭环在触发层的最后一处残留**，前两轮压缩了两次，仍未清零。
2. EXP-22 的「误报 ≤1/3」阈值是拍的，无经验依据。
3. L2 的实际形态（prompt、返回格式、失败时是否阻塞输出）本轮未定义，首次运行时按最小可用形态起，之后据实调整。
