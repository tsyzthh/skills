# 想法收敛（proj-shape）

以 **AI 为杠杆、以实现为讨论终点**：把模糊想法通过多轮留痕讨论磨清楚——客观、理性；不是泼冷水，也不是谄媚。使用者只需提供模糊想法，本 skill 负责提问、查证、结构化与沉淀。

**讨论归本 skill；编码与排期不归本 skill。** 对尚无现成解法或科研前沿的方向，讨论产出必须是**可交给落地阶段去跑验证**的尝试方案，并写明**继续**与**中止**标准。

## 与分析层方法 skill 的分工

proj-shape 是**讨论框架**，分析层调用一个**讨论方法 skill** 来产出本轮见解；默认推荐 `proj-experts`，可替换。

| | 分析层方法 skill | proj-shape（本 skill） |
|---|------------------|--------------------------|
| 核心问题 | 本轮要拿到什么洞见？（按方法定义） | 多轮间整体上要弄清什么？试什么？何时继续/停？ |
| 时间尺度 | 单次（一轮内） | 多轮（跨次对话） |
| 状态 | 无状态 | 有状态（`docs/discuss/`） |
| 产出形态 | 文本回答 + 方法自定义结构 | 文件（轮次 md + DECISIONS.md） |
| 边界 | 可单独使用 | **不写** MVP/排期/代码；**可写** 验证尝试、继续/中止、就绪判断 |

**默认方法**：`proj-experts`（谁最懂、事实查证、专家视角，输出按三档标签）。其他可选方法见「讨论方法的最小约定」段。

**建议配合使用**：每轮讨论中，分析层调用所选方法 skill；本 skill 负责讨论框架、文档目录与轮次沉淀。

## 三段式入口（首次使用本 skill）

把一个**新项目**的想法收敛过程拆成三段，每段产出独立留痕、退出条件明确：

| 阶段 | 产出 | 主导 | 退出 → 下一阶段 |
|------|------|------|-----------------|
| **0. BRAINSTORM** | `docs/discuss/BRAINSTORM.md`（[模板](assets/brainstorm-template.md)） | 用户写 | 5 个开放问句**至少答 3 个** + 自由叙述区非空 |
| **1. 苏格拉底澄清轮** | `docs/discuss/01-苏格拉底澄清.md`（`discussion_method: socratic-grounded`） | AI 提问、用户答 | 至少**提炼出 1 条可被外部专家评判的具体命题**（候选 `ORD` / 候选 `EXP` 假设） |
| **2+. 专家讨论轮** | `docs/discuss/02-….md`、`03-….md` …（默认 `discussion_method: proj-experts`） | AI 调用所选方法 skill | 按「[讨论就绪](#讨论就绪可否进入落地)」硬条件 |

**规则**：

- BRAINSTORM 是**用户自留草稿**，不是讨论文档：不写事实查证、不写专家视角、不产出 `INV`/`ORD`/`EXP`；越简短越好。
- BRAINSTORM **进入 round 02（第一轮专家讨论）后冻结**；苏格拉底澄清轮中允许回改（苏格拉底的价值之一就是让用户发现"原来我真正想做的不是这个"）。
- 苏格拉底澄清轮**默认推荐但可跳过**——若用户在 BRAINSTORM「给 AI 的话」节或对话中明示「想法够清楚，直接进专家轮」，则 round 01 直接走 `proj-experts`；该选择需在 round 01 frontmatter `discussion_method` 字段留痕。
- 苏格拉底澄清轮**默认单轮**——继续追问意味着已可进入专家攻防；如必要多轮，文件名 `01-苏格拉底-焦点A.md`、`02-苏格拉底-焦点B.md`，专家轮从 `03-` 起。
- 苏格拉底澄清轮**只提炼命题，不下决定**：本轮不应产出 `INV`/`ORD`（除非用户显式确认升级）；命题以「候选 ORD」「候选 EXP 假设」形式落到「本轮决定 → 待确认」节，留给专家轮攻防。

### 苏格拉底六问类别（AI 按需挑用，非全套打）

按 BRAINSTORM 内容挑 **3–5 个最值得追问的点**——不要一口气走完六类，会变成审讯。每个追问产出的命题写入 `01-苏格拉底澄清.md` 的「本轮决定 → 待确认」节作为候选 ORD / 候选 EXP 假设。

| # | 类别 | 问法示例 |
|---|------|---------|
| 1 | **澄清** | 「你说 X 是什么意思？能举一个具体例子吗？」 |
| 2 | **追假设** | 「你这里假设了 Y，这个假设的依据是什么？反例是什么？」 |
| 3 | **找原因** | 「为什么这个比那个重要？凭什么这么排序？」 |
| 4 | **看推论** | 「如果 Z 成立，会推出什么后果？你能接受最坏推论吗？」 |
| 5 | **换视角** | 「反对方会怎么说？跳出来看，这个问题问对了吗？」 |
| 6 | **元问** | 「这个问题本身是不是问对了？真正的问题是什么？」 |

**态度**：六问的目的是帮用户**发现**自己的想法，不是辩论或挑刺；当用户卡壳时换一类问法、给具体二选一选项降低表达负担，而不是反复追同一问。

**不抽 skill 的理由**：六问类别足够薄，inline 在本 skill 即可；未来若有跨项目复用需求再抽出 `socratic-grounded` 独立 skill。

### 澄清协议（先诊断后单问 · ORD-46）

> 来源：用户于 round 28 提供的 prompt（grounded：The Coaching Habit one-question discipline + Assumption Surfacing）。**模糊想法 / 新议题的首次回应必用**；明确指令、执行请求、GATE 确认等**跳过**（只在澄清点用，避免仪式化）。

1. **先诊断后回答**（3 步，固定顺序）：
   a. 指出用户**未明说但已默认的假设**（≥1 条，挂靠具体对象）；
   b. 列出**还缺的关键信息** + 各自如何改变结论（「若 X 为真 → 答案偏向 Y」）；
   c. 指出**这类问题最常见的 1 个错误**（挂靠该问题类型 + 写中招后果——无对象泛话=不合格，ORD-38 约束）。
2. **单问等答**：诊断后只提**一个**最关键的问题，等用户回答后再给完整输出（一次一问）。
3. **追问菜单**：等答后按需进入上方六问（挑 3–5 个最值得追问的点）。
4. **降级条款**：连续 3 次诊断套话或无增量 → 撤销诊断步骤，仅保留「单问等答」。

### 覆盖提问（防遗漏 · ORD-50）

> 承接用户诉求「基于人的非专业性与模糊性，避免后续讨论有遗漏」。**形态经 EXP-15 六视角裁决**：不做「AI 预生成的多维度大纲」，改为 **pause point 上的一次提问**（Gawande communication checklist：不规定怎么解决，只规定到某时点必须就某方面对话一次）。

| 项 | 规则 |
|----|------|
| **形态** | **不产生任何 artifact**——无覆盖表、无 status 列、无常驻文件；回答按**普通散文**进入当轮文档，不占人的 ≤5 阅读额度（INV-01）|
| **时点**（**2026-08-28 修订 · 只改时点不改问法**）| 仅 **2 个 pause point**：① **苏格拉底澄清轮之后的下一个工作段开始时**（隔至少一次上下文切换，**不在澄清轮末尾立刻问**）；② 就绪评估前。**中间轮次不问**（常驻提示会反转为有害：Nückles 2010 实验 2 中常驻组学期末显著劣于渐隐组）。<br>**为什么挪 ①**：刚讨论完时内容仍在工作记忆里，自评被「当下可及性」污染——延迟自评准确度 G=+.90 vs 即时 G=+.38（[Nelson & Dunlosky 1991](https://doi.org/10.1111/j.1467-9280.1991.tb00147.x) · DECISIONS `FACT-09`）。② 本就是延迟的，不动 |
| **问法（provisional · 待 EXP-17）** | 「**把你这个想法讲给一个完全不懂的人听，哪一段你自己讲不下去？**」——**只固定问法、不固定维度**：问法跨轮稳定故可对齐，缺口由用户当场涌现故不锚定 |
| **禁止（S1）** | **不得由 AI 预生成固定维度分类法**（「技术/商业/营销」式）。那是训练分布里的平均项目骨架而非本项目的地图；且给出类别会**收窄被探索的类别数而不减少产出量**（fixation 实证），专门骗过用户对「我讨论够了吗」的自我评估 |
| **措辞（S2 + ORD-33）** | 必须**结构性**：「我没在前面几轮看到 X」（可核对、零误报）。**禁语义性**：「X 讨论得不够 / 已覆盖 / 完整」——语义充分性判断属明令不自动化的一类，且对非专家制造 guilt |
| **留痕** | 回答写入当轮文档正文即可；**EXP-17 期间**额外在当轮「讨论」或「开放问题」节标一句「覆盖提问：问了什么 / 答出什么」，供 EXP 计数 |
| **退休条件** | 连续 **2 次**提问零新增「未谈过」项 → **停用本机制** |

**降级路径 B**（EXP-17 中止时）：改为每次从讨论内容涌现候选缺口 + AI 给 2–3 个候选供用户挑（降低表达负担，代价是重新引入 fixation 风险，须显式标注「以下为候选，可能不适用于你的项目」）。

### 讨论线 WIP 与中断留痕（ORD-52）

> 依据 Kanban Guide 工作流定义的最低必需项：「一份关于 WIP 将如何被控制的定义」+「**任何对 WIP 控制的可接受例外都必须被显式化**」。本项目实测症状：图谱线停滞 15 轮，用户自述「想做，排不上，更严重的是有畏难情绪」——**它从未被宣布暂停，只是静默停住了**。本条要治的就是「静默」。

| 项 | 规则 |
|----|------|
| **WIP 单位** | `DECISIONS.md` 的 `pipeline-state.threads` 中 `state ∈ {open, blocked}` 的条数 |
| **上限** | **3**（**C7 机检**）。`paused` / `closed` **不计入**——它们是「明确放下」的决定 |
| **例外条款（= 中断协议）** | 允许中断，但**必须留痕**：把被中断的线显式置 `paused` 并填 `blocked_on`（≤30 字符）。**禁止静默搁置** |
| **超限时** | validator 退非 0。处置只有两条：把某条置 `paused`/`closed`；或明确承认要同时背更多并调高上限（**须走 GATE 且留痕**）|
| **停滞可见性** | validator 每次运行打印各线停滞轮数（= 当前最大轮次 − `last_round`，**派生不存储**）——这是「什么卡住了」的直接答案，此前系统内不存在 |

**这条机制的真正价值**：把「静默停滞」变成「必须做的一个决定」。开第 4 条线时，你被迫回答「那前面哪条放下」——而这正是图谱线 15 轮里从未被问过的问题。

## 项目目录结构（本 skill 定义）

在**当前工作区根目录**（用户正在讨论的那个项目根，不是 skill 包目录）维护：

```text
docs/
└── discuss/
    ├── BRAINSTORM.md         # 用户自留：初始想法草稿（首次使用本 skill 时自动创建空模板）
    ├── DECISIONS.md          # 已确定决定汇总（其它 skill / 用户优先读此文件）
    ├── 01-苏格拉底澄清.md     # 默认 round 01：苏格拉底六问提炼候选命题
    ├── 02-技术选型争议.md
    └── 03-范围收敛.md
```

### 约定

| 项 | 规则 |
|----|------|
| 目录 | 固定为根目录下的 `docs/discuss/`；`docs/` 与 `discuss/` 不存在则一并创建 |
| 文件名 | `{轮次编号}-{讨论主题}.md` |
| 轮次编号 | 两位数字，`01` 起，按已有文件最大编号 +1；**不重编号、不覆盖旧轮** |
| 讨论主题 | 简短概括本轮焦点；文件名用 **kebab-case 英文** 或 **简短中文**（二选一，同一项目内保持一致）；禁止 `/ \ : * ? " < > \|` |
| 一轮一文件 | 每轮讨论结束写入**新文件**；上一轮文件只读不改（历史留痕） |
| 决定汇总 | 固定文件 `docs/discuss/DECISIONS.md`；**可更新**，存放当前有效的全部已确定决定 |
| 索引（可选） | 可在 `docs/discuss/README.md` 维护轮次列表；非必须 |

### DECISIONS.md（决定汇总）

**目的**：其它 skill 或用户无需重读全部轮次，即可获知已达成共识。

| 项 | 规则 |
|----|------|
| 路径 | `docs/discuss/DECISIONS.md`（全大写，固定名，不参与轮次编号） |
| 初建 | 首次有**已确定**决定时，按 [assets/decisions-template.md](assets/decisions-template.md) 创建 |
| 更新时机 | 每轮讨论结束，将本轮「已确定」条目合并进汇总；无新决定则只更新「最后更新」_meta_（可选跳过） |
| 决定分类 | 见下表 |

| 类型 | 含义 | 修订规则 |
|------|------|----------|
| **原则性不变量** | 方向性、伦理或架构底线；违背则相当于换项目 | 仅当用户**显式**推翻或修改时变更；须在「变更日志」记原因 |
| **普通决定** | 当前有效的技术/范围/偏好选择，可依新证据调整 | 可在后续轮次修订；旧条目移到「变更日志」或标 `已废止` + 指向新 ID |

**ID 编号**：不变量 `INV-01`…；普通决定 `ORD-01`…。新增用下一可用号，不重用已废止 ID。

**来源（必填）**：每条决定必须注明**来源**，无来源不得写入汇总。来源用于追溯「谁/在哪一轮/依据什么」确立该决定。

| 来源类型 | 写法示例 |
|----------|----------|
| 讨论轮次 | `` `03-范围收敛.md` §本轮决定 `` 或 `` 轮次 03 §讨论 `` |
| 用户明示 | `` 用户 @轮次02 原话：「…」 `` 或 `` 用户于本轮确认 `` |
| 查证事实 | `` [文档标题](URL) `` 或 `` repo/issue#123 `` |
| 方法推理 | `` 推理 · [方法/角色]；依据 [URL] 的 [原则/方法步骤] … ``（如 `推理 · 模拟推理 · Karpathy；依据 [URL] 的 [原则]`） |
| 废止/修订 | 变更日志中写明 `` 废止 ORD-02 来源；见 `05-…md` `` |

可组合多条来源，用分号分隔。禁止只写「讨论得出」而无轮次文件或用户/URL 指向。

**写入门槛**：仅写入**双方已确认**或用户明确说「就按这个」的条目；尚在争论的放在当轮文档的「待确认」中，**不得**提前写入汇总。

**讨论状态**（写在 `DECISIONS.md` 文首，每轮可更新）：

| 状态 | 含义 |
|------|------|
| `exploring` | 方向与问题空间仍在探索 |
| `deciding` | 主要权衡进行中，仍有未闭合决定 |
| `ready-for-implementation` | 满足「讨论就绪」清单（见下），可交给落地 skill/任务 |
| `blocked` | 存在阻塞性开放项，需先讨论或先跑 `EXP-xx` |

设为 `ready-for-implementation` 须用户**显式确认**或明确授权代选；agent 不得单方面宣布开工。

**待验证尝试**（`DECISIONS.md` 专表，ID `EXP-01`…）：

针对**无现成方案 / 前沿 / 关键未证实假设**，讨论阶段必须产出可验证尝试（非完整产品）：

| 字段 | 要求 |
|------|------|
| 假设 | 本条尝试要证实或证伪什么 |
| 尝试方案 | spike/PoC/文献复现/对照实验；范围足够小，可在落地阶段执行 |
| 成功信号 | 可观测、可判定（指标、现象、交付物） |
| **继续** | 满足何条件 → 进入更深讨论或交给落地扩大投入 |
| **中止** | 满足何条件 → 停止该线、降级路径 B 或标 `blocked`（须写入决定或新 EXP） |
| 来源 | 同决定来源规则 |
| 执行状态 | `pending` / `running` / `passed` / `failed`（由**落地阶段**更新；讨论轮次可置 `pending`） |

尝试方案写在讨论里，**汇总表在 DECISIONS**；与轮次文档**互相同步**（同决定规则）。无前沿未知时，本表可空。

**给其它 skill 的约定**：落地/实现前读 `DECISIONS.md`（决定 + `EXP-xx` + 讨论状态）；按「继续/中止」与成功信号执行验证，勿 reinterpret 未查证内容为定论。

### 承重事实（K）与语气二分（INV-05 / ORD-53）

> **完整操作细则见 [assets/k-facts.md](assets/k-facts.md)**（字段规则 / 三态与三值的理由 / 状态传播 / C8 / 退出条件）。本节只给必须记住的部分。
> **出处（借鉴，非自创）**：需求工程 **indicative / optative** 二分与 `S ∧ K ⊢ R`——Zave & Jackson [Four Dark Corners](https://doi.org/10.1145/237432.237434)；决策论侧 Savage 把 belief 与 desire 分离。

| | **indicative（断言）** | **optative（偏好）** |
|---|---|---|
| 说的是 / 有无真值 | 世界是怎样的；有，可证伪 | 我们要什么；无，只有代价 |
| 验证方式 | **验证为真**（查证 + 出处） | **验证为被认可**（人拍板） |
| 谁说的重要吗 | **不重要**——用户说的断言不比 AI 说的更权威 | **只有人说的算**——AI 无权替人选 |
| 载体 | §承重事实（K）+ §待验证尝试（EXP = 未验证的 K）| §原则性不变量 + §普通决定 |

**不要去逐句分析语气**——作者本人否决了逐句判定（「avoid grammatical distinctions of mood **within a single description** … indicate the mood **by its place**」），因为部署后 optative 会变成 indicative，逐句判定届时要求重写描述本身。本 skill 只要求一件事：

> **承重陈述必须落进一个容器；禁止停留在无容器的散文里。**
> 承重判据 = **它出现在某条 INV/ORD/EXP 的论证前提里**（若为假 → 该条决定失去支撑）。

**反向驱动**（别从事实侧问「登记全了吗」——域不可枚举且判据自指）：在**每条新增/修订决定**的「本轮决定」节写 `前提(K)`（可显式 `none`）；承重的登记进 §承重事实（K）并回填 `FACT-xx`。**向前生效，历史不回填。**

**动因（两起同形事故）**：① 一条外部 runtime 事实过期，**六周无人发现**，其间一条 ORD 一直悬在上面；② 用户把「code graph 由 LLM 生成」当背景事实用（实为 tree-sitter 抽 AST 的纯程序步骤），走了冤枉路。两起都不是查证能力不足，是**陈述没有 home**。

**已知未闭合风险（诚实披露）**：「表会被填成终态、然后没人复查」这条反对**未被驳倒**（开源 ADR 实测约 63% 创建即 accepted）→ 带 **EXP-19 / EXP-20** 观测与明确撤表降级路径，见 [assets/k-facts.md](assets/k-facts.md) 末节。

### BRAINSTORM.md（初始想法草稿）

**目的**：在 AI 介入讨论之前，让用户**以最低负担**把想法说个大概，为后续苏格拉底澄清轮提供起点；详见上文「[三段式入口](#三段式入口首次使用本-skill)」。

| 项 | 规则 |
|----|------|
| 路径 | `docs/discuss/BRAINSTORM.md`（全大写，固定名，不参与轮次编号） |
| 创建 | 工作流 §0 中**自动创建**（按 [assets/brainstorm-template.md](assets/brainstorm-template.md)）；由用户填写 |
| 完成门槛 | 5 个开放问句**至少答 3 个** + 自由叙述区非空（最低门槛，不强求完整） |
| 冻结时机 | 进入 **round 02（第一轮专家讨论）** 后冻结；苏格拉底澄清轮中可回改 |
| 决定关系 | **不写入决定**——不产出 `INV`/`ORD`/`EXP`，仅是讨论起点；决定经苏格拉底轮和专家轮逐步沉淀 |
| 同步要求 | 不在 DECISIONS / 轮次同步检查清单内——它是讨论前置物，不是讨论留痕 |

**禁止**：把 BRAINSTORM 当成正式讨论文档去补充事实查证 / 专家视角 / 方法专属输出——这些属于轮次文件的职责；BRAINSTORM 越简短越好，让步骤往下走比写得完美更重要。

### 讨论就绪（可否进入落地）

讨论**足够** ≠ 所有问题有答案；= **最小决策集已闭合，最大未知已变成可执行验证**。

**硬条件**（全部满足才可标 `ready-for-implementation`）：

1. **成功标准**已写入 `INV` 或 `ORD`（做成什么样、非目标是什么）。
2. **无阻塞性待确认**：影响路线/范围的开放项，要么已决定，要么已登记为 `EXP-xx` 且具备成功信号与继续/中止标准。
3. **前沿/无现成方案部分已降级**：至少一条路径——「若 EXP-xx 失败则 ORD/方向 B」；不得只有「再想想」。
4. **原则性不变量**不在摇摆中（若本轮修改了 INV，状态应保持 `deciding`）。
5. **盲点双问已执行且每条答案有落点**（见下节）。

**软信号**（满足越多越好）：范围边界清楚；风险有来源；事实/推理/待验证已分开。

**仍不够**：反复争论同一 INV；开放问题全是「能不能做」而非「试哪条」；大量未查证却计划重投入。

就绪结论写入 `DECISIONS.md`「讨论就绪检查」小节（模板见 [assets/decisions-template.md](assets/decisions-template.md)）。

#### 盲点双问（就绪前最终检查 · 硬条件 5）

标 `ready-for-implementation` 前，AI 必须回答两个固定问题（语义固定，措辞可按语境改写）：

| 问 | 对象 | 内容 |
|----|------|------|
| Q-AI | AI 自答 | 「眼下我最没把握的是什么？」 |
| Q-人 | AI 向用户提出 | 「当前情况你最大的遗漏是什么？」——AI 给出候选答案，用户确认或补充 |

**闭环规则**（防「永远讨论下去」——验收是未知**入册**，不是未知**清零**）：

1. **单次执行**：每次就绪评估内双问只执行一遍（对齐 pre-mortem 单 session、gate 当天出决策）；不循环追问。
2. **三选一落点**：每条答出的条目当场处置——**已有 INV/ORD 覆盖** / **登记为 `EXP-xx`**（含成功信号 + 继续/中止）/ **用户明示接受为已知风险**。「再讨论一轮」不是合法落点；若条目确实阻塞且用户不接受 → 状态回 `deciding` 走正常轮次（是既有流程回退，不是双问在循环）。
3. **接受留痕**：明示接受的条目具名写入 `DECISIONS.md`「讨论就绪检查」小节（条目 + 日期），可追溯可复查——防为过门槛滥答「接受」。
4. **增量重问**：本次未过、再次尝试 ready 时，已处置条目**不重开**（除非新证据），只问新增的没把握/遗漏。

若各轮「开放问题」首条（本轮 AI 最没把握的点，见 [assets/round-template.md](assets/round-template.md)）已持续维护，本检查退化为 DO-CONFIRM 式核对累积清单，成本极低。

出处：`docs/discuss/20-盲点双问与每轮不确定性显化.md`（Klein pre-mortem 时机与单 session / Cooper Stage-Gate 有限枚举结局 / PMBOK Accept 终局处置，含 URL）。

### 对 proj-plan 的承诺字段（衔接下游）

proj-shape → proj-plan 的唯一衔接点是 `DECISIONS.md`。当讨论状态变为 `ready-for-implementation` 时，DECISIONS 必须为 proj-plan 准备好以下字段（否则 proj-plan 的 Round B GATE-1 / Coach hybrid 无法定模式）：

| 字段 | 必备程度 | proj-plan 用途 |
|------|---------|---------------|
| `INV` / `ORD` 区分 | INV 至少 1 条 | tailoring T/F 模式判断；charter 不可变约束 |
| 成功标准 | 写入 INV 或 ORD（做成什么样、非目标是什么） | charter 验收基线；phase-roadmap 里程碑判据 |
| 范围边界 | 写入 ORD（含非目标） | WBS 范围；phase-roadmap 划分 |
| `EXP-xx` 降级路径 B | 每条 EXP 必填「中止 → 降级方向」 | analyze gate 风险评估；circuit breaker 触发 |
| 决定来源 | 全字段必填 | proj-plan change-log 可追溯 |

**自检**：进入 `ready-for-implementation` 前对照上表；缺项即不得提交。proj-plan 读到缺项时应**回退本 skill 补齐**而非自行补全。

### 轮次文档 ↔ DECISIONS 互相同步（强制）

`docs/discuss/NN-主题.md` 与 `docs/discuss/DECISIONS.md` 中**已确定决定**必须保持一致；**禁止**只更新其一就结束本轮。

| 方向 | 规则 |
|------|------|
| 轮次 → 汇总 | 当轮「已确定」写入 `NN-主题.md` 后，**同一轮对话内**合并进 `DECISIONS.md`；轮次中标注对应 `INV-xx` / `ORD-xx` |
| 汇总 → 轮次 | 修订/废止 `DECISIONS.md` 某 ID 时，**同一轮对话内**在**当前轮次**或**来源轮次**留下同步记录（见下） |
| 一致性 | 两处「决定」条文须一致；来源列须能互相指向（汇总来源含轮次文件；轮次同步节含 ID） |

**当轮同步（默认）**：新建或修订决定时，步骤 4–5 合并为一次**同步写入**——先定稿当轮「本轮决定」，再更新 `DECISIONS.md`，最后在当轮文末填写「DECISIONS 同步状态」。

**修订历史轮次确立的决定**：历史轮次正文不改；在**来源轮次文件末尾追加**（仅此节可追加，不改上文）：

```markdown
## 同步注记（{YYYY-MM-DD}）

- {操作} `ORD-02` → 已废止，由 `ORD-05` 取代；见 `DECISIONS.md` 变更日志
```

若来源轮次不可改，则在**当前轮次**的「本轮决定 → 对既有决定的修订」中记录，且 `DECISIONS` 来源列写明 `` 修订见 `06-…md` §对既有决定的修订 ``。

**同步检查清单**（每轮结束前自检）：

- [ ] 当轮每条「已确定」在 `DECISIONS.md` 有对应 ID，且条文一致
- [ ] `DECISIONS.md` 每条有效 ID 的来源指向正确轮次
- [ ] 当轮「DECISIONS 同步状态」已填写；有修订时来源轮次或当轮已有同步注记
- [ ] 无「仅存在于汇总」或「仅存在于轮次」的已确定决定
- [ ] 每条 `EXP-xx` 在当轮有对应描述，且含继续/中止标准；或确认本轮无待验证尝试

### 轮次编号算法

1. 列出 `docs/discuss/` 下匹配 `^\d{2}-.+\.md$` 的文件（**不含** `DECISIONS.md`）。
2. 若无文件 → 本轮为 `01`。
3. 若有 → 取最大编号 +1，格式化为两位（`09` → `10` 时仍用两位，超过 99 用三位亦可，但同一项目内格式一致）。

### 主题 slug 建议

- 从用户本轮关注点提炼，如 `范围边界`、`是否用-rag`。
- 过长则截断到约 30 字符（按字符计，非字节）。

## 原则（讨论层）

1. **默认可行** — 讨论中先探索「在什么条件下成立」，再谈「什么条件下可能不成立」。
2. **障碍必须带路** — 指出风险时，同步给出可讨论的缩小范围、替代路径或待验证问题（**不写** MVP/排期）。
3. **不谄媚** — 避免空泛表扬；用可检验的表述。
4. **不泼冷水** — 避免「这不行」式开场；用「若坚持 A，需面对 B；可改为 C」。本条是讨论框架兜底；**分析层所选方法 skill 自身的态度规则优先**（如 proj-experts principle #10 建设性优于否定）。
5. **分析有据** — 见下文「事实基础」；事实写入当轮文档的「已查证事实」节。
6. **职责边界** — 不写 MVP 排期与代码；**要写** 可验证尝试及继续/中止标准，供落地执行。
7. **未知前置** — 无现成解法时，禁止假装已有答案；必须落到 `EXP-xx` + 继续/中止，而非无限讨论。

## 无现成方案 / 科研前沿（讨论专轨）

当查证后仍无工业界/playbook 方案，或属研究前沿时，本轮讨论**必须**包含：

1. **问题分解** — 哪些是已查证事实、哪些是推理（来自所选方法）、哪些是真正未知。
2. **至少 1 条 `EXP-xx`**（可多条）— 最小可验证尝试；时间/成本量级可粗估（数量级即可，不做排期）。**上游方法若产出 testable 假设**（如 proj-experts 4b 三件套的"待验证假设 + 中止信号"、pre-mortem 的失败假设等），升级为完整 `EXP-xx`（补 `尝试方案`、`成功信号`、`执行状态`、`降级路径 B`）。
3. **继续标准** — 例如：「复现 baseline 达论文 x%」「用户访谈 n≥5 且 ≥3 人愿付费」。
4. **中止标准** — 例如：「2 周内无法复现」「核心指标低于阈值 T」「用户明示放弃该方向」；并写明 **降级路径 B**（缩小范围 / 换方法 / 暂停项目）。
5. **推理类输出仅作尝试设计依据** — 不论来自哪种方法（proj-experts 的【模拟推理】、其他方法的推导），都须标注来源；不得将推理写入 `INV` 除非用户确认为不变量。

讨论结束语应明确：**落地阶段去执行哪些 EXP，用什么判定继续/停**——不在本 skill 内执行。

## 失败模式（必须避免）

- **跳过事实直接讨论** — 未查证或未标「未验证」就下技术/市场结论。
- **只列风险不给讨论方向** — 审辩会式泼冷水。
- **把推理类输出当定论** — 未区分**已查证事实 / 推理 / 待验证假设**（不论推理来自哪种方法）。
- **覆盖或篡改历史轮次文件** — 破坏 SDD 式留痕。
- **在本 skill 中写落地计划** — MVP、里程碑、24–72h 任务列表等属越权。
- **决定只写在轮次里不更新 DECISIONS.md** — 导致后续 skill/用户必须通读全部历史。
- **把未确认草案写入 DECISIONS.md** — 污染汇总，破坏信任。
- **决定缺少来源** — 后续无法追溯，其它 skill 无法判断可信度。
- **轮次与 DECISIONS 不同步** — 只改一个文件；或两处条文/ID 不一致。
- **前沿问题空泛讨论** — 无 EXP、无继续/中止，只有「需要更多研究」。
- **过早 ready-for-implementation** — 无用户确认、硬条件未满足。
- **盲点双问变循环追问** — 要求「没把握清零」才放行、或把「再讨论一轮」当落点；正确做法见「盲点双问」闭环规则（入册即可，接受是正当终局）。
- **「最没把握的点」套话化** — 条目不挂靠本轮具体对象、不写「若为假影响哪条决定」，或下一轮轻量框定不处置它（写「需要更多验证」式泛话等同未答）。
- **在 docs/discuss 里写实现排期** — 越权；只写验证内容与判定标准。
- **把方法 skill 的推理压成无来源总结** — 不论是 proj-experts 的【模拟推理】还是其他方法的推导，写入文档时缺少**来源 + 原则/方法步骤 + URL** 挂靠，等同 WebSearch + agent 归纳。
- **维度表套表化** — 全轮强制出表 / 把纯时序状态塞进维度 → 维护负担反噬（Goldratt 测量成本 + Gawande 坏 checklist）；正确用法 = 可选段 + 高危维度优先 + 冲突行高亮（ORD-43）。
- **覆盖提问变成维度点名（ORD-50）** — 把「哪一段你讲不下去」换成「技术/商业/营销你谈了吗」，或列一张维度表让用户逐格确认。这正是 EXP-15 六视角独立否决的形态：给出类别会**收窄被探索的类别数而不减少产出量**，用户会觉得「讨论很充分」而实际范围收窄。也不得说「X 讨论得不够」（语义判断 + 对非专家制造 guilt），只能说「我没在前面几轮看到 X」。

- **把用户口中的断言当背景事实直接用（INV-05）** — 用户说「业界都是这么做的」「X 做不到 Y」时，这是**可证伪的断言**不是偏好，却因为它裹在方案陈述里而被当成前提直接往下做。判据不是「谁说的」而是「这是哪一类」：断言就该查证，**用户说的断言不比 AI 说的更权威**。反向的错误同样是失败——**质疑用户的偏好**（那是夺权，违反 Supervised-AI）。

- **K 表变成事实垃圾场 / 或反过来空着（ORD-53）** — 把所有查到的事实都往 §承重事实（K）里塞（判据是「出现在某条决定的论证前提里」，不是「这条事实重不重要」），或反过来每条决定都写 `前提(K): none` 走过场。两者都会触发 EXP-19 的中止条件 → 撤表。**非承重事实留在轮次文档「已查证事实」节，那是它正确的 home。**

- **澄清协议仪式化 / 一次多问 / 诊断套话** — 对明确指令也强跑 3 诊断、或一次抛多个问题、或组件 ③ 写无对象泛话（「人们常犯沟通错误」式）→ 触发 ORD-46 降级条款；正确用法 = 仅新议题首次回应用 + 单问等答 + 挂靠对象与后果（ORD-46）。

## 事实基础（每轮必做）

讨论正文写入文档前，先完成事实整理（可写在文档的「事实与假设」节）。

### 分析层 vs 写入层

| 层 | 执行 | 产出去向 |
|----|------|----------|
| **分析层** | 完整执行本轮所选**讨论方法 skill** 的工作流（默认 proj-experts：轻量框定 → 定向查证 → 专家模拟 / 模拟推理） | 内存/对话中完成，**不要求**原样粘贴其方法专属 Markdown 格式 |
| **写入层** | 按 [assets/round-template.md](assets/round-template.md) **重组**进轮次文档 | `docs/discuss/NN-主题.md` 的「事实与假设」等节 |

**写入层信息下限**（任何方法、任何格式下均不得省略）：

1. **轻量框定** — 3–5 个定向查证问题（若所选方法要求查证；表格或列表均可）。
2. **已查证事实** — 每条附 URL 或可追溯出处。
3. **推理类输出** — 显式标注（不论来自哪种方法：best-minds 的【模拟推理】、pre-mortem 的失败假设推导、socratic 追问得出的中间结论等）；每条须含 **方法/角色 + 依据 + URL** 三元组。
4. **三分离** — 已查证事实 / 推理 / 待验证假设 不得混写（方法无关；具体方法的内部标签如 best-minds 的三档作为方法内部细节）。
5. **外部前提复查（ORD-39）** — 轻量框定与就绪评估时，复查 DECISIONS「外部前提登记」表被本轮触及的条目是否过期；复查结果留痕（日期+结论）。

**禁止**：将方法 skill 的输出压成无来源的 agent 总结（如「推理 A / 推理 B」且未挂方法/角色身份）。

### 讨论方法调用约定

本 skill 通过分析层调用一个**讨论方法 skill**；默认 `proj-experts`（`skills/proj-experts/` 或 `~/.cursor/skills/`、`~/.claude/skills/`）。

| 项 | 规则 |
|----|------|
| 默认方法 | **Round 01** 默认 `socratic-grounded`（苏格拉底六问 inline 在本 skill，见「[三段式入口](#三段式入口首次使用本-skill)」）；**Round 02+** 默认 `proj-experts`（适用绝大多数架构/方向/选型讨论） |
| 跳过苏格拉底 | 用户明示「想法够清楚，直接进专家轮」时，round 01 直接走 `proj-experts`；该选择在 BRAINSTORM「给 AI 的话」或 round 01 frontmatter 留痕 |
| 切换方法 | 用户**显式指定**本轮用其他方法 skill（如 `pre-mortem`、`five-whys`）；不指定则用默认 |
| 方法记录 | 写入 `round-template.md` frontmatter 的 `discussion_method` 字段 |
| 方法约束 | 见「讨论方法的最小约定」段 |
| 多方法 | 同一轮原则上**单方法**；若混用须在轮次文档分节标明 |

**Fallback：方法 skill 不可用 / 无联网时**

1. 列出 3–5 个待查问题 → **定向 WebSearch**（官方 docs / repo / issue / RFC）。
2. 查不到则标「未查证 / 低置信」；禁止专家口吻臆测。
3. 无联网时：标低置信，列出待验证假设，讨论粒度相应收紧。

### 写入层格式分级

按本轮讨论类型选用写入格式；**分析层始终完整执行所选方法**，仅写入详略不同。

| 级别 | 适用场景 | 轮次文档要求 |
|------|----------|--------------|
| **完整** | 架构/方向争议；多角度碰撞；尚无 `ORD`/`INV` 共识；推理将写入决定 | 「方法专属输出」节**必填**：沿用所选方法 skill 的结构（proj-experts 时即 `视角 A/B…` + 三档标签【原话】/【已公开立场】/【模拟推理】；其他方法按其约定）；详见所选方法 skill 文档 |
| **轻量** | 决定收敛；执行细节；前轮事实已确立；本轮主要为同步 `DECISIONS` | 可省略独立「方法专属输出」节；**推理类条目仍须**在「推理」节逐条标注方法/角色/依据/URL |
| **最小** | 纯用户确认轮；无新查证、无新推理 | 仅更新决定与同步状态；「事实与假设」可写「本轮无新查证」 |

**争议轮判定**（满足任一即按 **完整** 级写入）：本轮存在未闭合的方案/架构权衡；动用 ≥2 个角度（如 best-minds 的 ≥2 专家、socratic 的多线追问、six-hats 的多色帽等）；本轮推理可能进入 `INV`/`ORD`/`EXP` 来源列。

**前置排除 · 裁决轮（ORD-49 修订）**：套用上述判定**之前**先问一句——**本轮所需的多角度分析，是否已由既有 artifact 覆盖**（前轮 / EXP 产物 / 案例库）？若**已覆盖且无新事实进入** → 本轮为**裁决轮**：按「轻量」级写入，**不触发** `proj-experts` 的红队与各视角独立检索（ORD-49），改为**消费既有材料 + 归约分歧 + 交人拍板**。理由：对已收敛的议题重跑多视角是复读，与 ORD-43「套表化」/ ORD-46「仪式化」同源。

**推理类条目格式（轻量/完整均须）**：

```markdown
- **推理 · [方法 / 角色]**：…；依据 [来源](URL) 的 [原则/方法步骤] …
```

> 示例（proj-experts）：`**推理 · 模拟推理 · Karpathy**：…；依据 [karpathy.github.io/...](URL) 的「LLM as simulator」原则 …`
> 示例（pre-mortem）：`**推理 · pre-mortem · 失败假设 #2**：…；依据本轮 pre-mortem step 3 输出 …`

完整级可在「方法专属输出」节展开，再在「推理」节做索引或合并——两处条文须一致，且均含三元组。

## 讨论方法的最小约定

任何方法 skill 作为本 skill 的分析层时，须满足以下**最小契约**（默认 `proj-experts`；未来可接入 `pre-mortem`、`socratic-grounded`、`five-whys` 等）：

1. **输出可归类** — 方法的产出必须能落入本 skill 的"事实 / 推理 / 待验证假设"三分类之一；不得产生第四类无法归位的内容。
2. **推理可追溯** — 推理类输出须挂得上 **方法/角色 + 依据 + URL** 三元组（best-minds 的"专家/原则/URL"是其中一种特化）。
3. **态度对齐** — 方法 skill 自身的态度规则（如"建设性优于否定"）优先；本 skill 的 principle #4 不泼冷水兜底。
4. **可与 EXP-xx 接续** — 若方法产出 testable 假设，须能升级为完整 `EXP-xx`（补尝试方案 / 成功信号 / 降级路径 B）。

> 本节只立**最小契约**，不立完整接口。待第 2 个方法 skill 实际接入时，再根据经验补充详细接口规约（避免过早抽象）。

## 工作流

### 0. 准备目录、BRAINSTORM 与轮次

- 确保 `{项目根}/docs/discuss/` 存在。
- **若 `BRAINSTORM.md` 不存在**：按 [assets/brainstorm-template.md](assets/brainstorm-template.md) 创建空模板（不需要等用户提问）；告知用户已创建并提示其填写；待最低门槛（5 问句答 3 个 + 自由叙述非空）满足后再进入 round 01。
- **若 `BRAINSTORM.md` 存在但本轮是 round 01**：
  - 复述 BRAINSTORM 要点，与用户确认是否已满足最低门槛；
  - 检查 BRAINSTORM「给 AI 的话」节是否明示跳过苏格拉底；未明示 → 默认走 `socratic-grounded`；明示跳过 → 走 `proj-experts`。
- **若本轮 ≥ round 02 且 BRAINSTORM 仍可改**：本轮落盘前**冻结** BRAINSTORM（追加冻结注记，正文只读）。
- 按「轮次编号算法」确定本轮 `NN`；与用户确认或提炼本轮「讨论主题」→ 确定文件名 `docs/discuss/NN-主题.md`（round 01 苏格拉底轮建议主题为 `苏格拉底澄清` 或更具体的焦点）。

### 1. 读取上下文

- **先读** `docs/discuss/DECISIONS.md`（若存在）——掌握全部已确定决定，再读细节。
- 读取最近 1–2 轮 `docs/discuss/NN-主题.md` 补全背景；**不必**通读所有历史轮次，除非 DECISIONS 不足或用户要求。

### 2. 澄清本轮意图

- 复述用户**本轮**输入（相对初始想法的新反馈、新问题）。
- 明确本轮讨论范围；信息不足时提问。
- **新议题首次回应按「澄清协议（ORD-46）」执行**：先 3 步诊断（假设/缺信息+敏感性/常见错误）→ 只问一个最关键的问题 → 等答后再输出（明确指令跳过）。
- **不写** MVP / 排期 / 实现清单。

### 3. 事实基础 + 讨论

- **确认本轮讨论方法**：
  - **Round 01** 默认 `socratic-grounded`（用户明示「直接进专家轮」时改用 `proj-experts`）；
  - **Round 02+** 默认 `proj-experts`；用户显式指定其他方法 skill 时按指定执行；
  - 记录到轮次文档 frontmatter 的 `discussion_method` 字段。
- 调用所选方法 skill，执行其完整工作流；**`socratic-grounded` 时**按本文件「[苏格拉底六问类别](#苏格拉底六问类别ai-按需挑用非全套打)」inline 执行——挑 3–5 个最值得追问的点，不必全套打。
- 按「事实基础」将方法产出**重组**进当轮文档（守住信息下限 + 三分离）。
- 在默认可行、障碍带路、不谄媚不泼冷水的约束下展开讨论（**所选方法自身的态度规则优先**）。
- 识别是否触发「无现成方案 / 科研前沿」专轨；若是，产出 `EXP-xx` 草案（含继续/中止）。
- 可含：方案对比、权衡、开放问题；对弱背景用户用少量具体二选一问题降低表达负担。
- **苏格拉底澄清轮特殊约定**（仅 `discussion_method: socratic-grounded` 时）：
  - 本轮**不产出** `INV`/`ORD`（除非用户显式确认升级），命题以「候选 ORD」「候选 EXP 假设」形式落到「本轮决定 → 待确认」节，留给后续专家轮攻防；
  - 默认**单轮**——继续追问意味着已可进入专家攻防；如必要多轮则文件名 `01-苏格拉底-焦点A.md`、`02-苏格拉底-焦点B.md`，专家轮从 `03-` 起；
  - 苏格拉底过程中若发现 BRAINSTORM 写反/写偏 → 允许用户回改 BRAINSTORM（在本 skill 工作流 §0「冻结时机」之前）。
  - **本轮结束时执行「覆盖提问」一次**（ORD-50 第 1 个 pause point）。

### 3b. 讨论就绪评估（每轮建议）

- 对照「讨论就绪」硬/软条件，更新 `DECISIONS.md` 的 **讨论状态**。
- 若用户问「能不能开始做」，如实列出未闭合项或建议确认的 `EXP-xx`，勿口头代替 `ready-for-implementation`。
- 拟标 `ready-for-implementation` 时：执行「盲点双问」（硬条件 5）——单次、三选一落点、接受留痕、增量重问。
- **就绪评估前执行「覆盖提问」一次**（ORD-50）——与盲点双问并列但问的不是同一件事：盲点双问问「最没把握 / 最大遗漏」，覆盖提问问「哪一段你讲不下去」。
- 交人确认状态/拍板前：用 1–3 句复述「要拍什么 + 拍下去的后果」，人核对后拍板；复述有偏先纠正（teach-back · ORD-44 · 只在拍板点用，全程使用 = 啰嗦）。

### 4–5. 同步写入轮次与 DECISIONS（原子步骤）

**不得**先写完轮次就结束；**不得**只改 `DECISIONS.md` 而不动轮次记录。

1. 使用 [assets/round-template.md](assets/round-template.md) 写入 `docs/discuss/NN-主题.md`（含「可验证尝试」节，若有）。
2. **立即**同步 `docs/discuss/DECISIONS.md`：已确定决定、`EXP-xx` 表、讨论状态、就绪检查（有变更时）；无则按 [assets/decisions-template.md](assets/decisions-template.md) 初建。
   - **每条新增/修订的 INV/ORD/EXP 须写 `前提(K)`**（可显式 `none`）；承重前提登记进 §承重事实（K）并回填 `FACT-xx`（INV-05 / ORD-53 · 向前生效不回填历史）。
3. 回填当轮 `INV`/`ORD`/`EXP` ID；填写 **DECISIONS 同步状态**。
4. 修订历史决定 / EXP：按「互相同步」追加 **同步注记** 或当轮「对既有条目修订」。
5. 执行「同步检查清单」；说明已更新路径；列出开放问题或待落地执行的 `EXP-xx`。

无已确定决定且无新 `EXP` 时：可只写轮次文档；**仅**可更新讨论状态/就绪检查，勿改决定表正文。

### 6. 可选：更新 docs/discuss/README.md

若项目已有或用户需要索引，追加一行：`NN | 主题 | 日期 | 一句话摘要`。

## 当轮文档结构

见 `assets/round-template.md`。核心章节：

- 元信息（轮次、主题、日期、**讨论方法**）
- 用户输入（本轮原文或摘要）
- 轻量框定（查证前问题清单；若所选方法要求查证）
- 已查证事实 / **推理** / 待验证假设
- **方法专属输出**（争议轮必填；收敛轮可省略；按所选方法 skill 的结构组织——proj-experts 时为「视角 A/B…」+ 三档标签结构）
- 讨论正文
- 需求维度表（可选段 · ORD-43：争议轮/就绪评估前建议；状态三值，冲突行高亮）
- 可验证尝试与继续/中止（前沿/无现成方案时必填）
- 本轮决定（已确定 / 待确认 / 修订）——**每条新增/修订决定必带 `前提(K)`**（`FACT-xx` 或显式 `none` · INV-05 / ORD-53）
- DECISIONS 同步状态
- 开放问题（供下一轮）——**首条固定**为「本轮 AI 最没把握的点」：须挂靠本轮具体对象（某 ORD/EXP/假设/事实）+ 写明「若为假影响哪条决定/方向」；无新增时可写「无 + 一句理由」（诚实的「无」优于凑数）；禁止「需要更多验证」式无对象泛话。**消费强制**：下一轮「轻量框定」必须显式处置该条目（采纳为查证问题，或一句话说明为何不查）。**降级条款**：连续 3 轮套话或未被下轮消费 → 撤销本固定条目，仅保留就绪门槛的盲点双问
- **禁止章节**：MVP 细则、里程碑排期、代码级实现步骤（尝试方案只写到验证粒度）

决定汇总结构见 [assets/decisions-template.md](assets/decisions-template.md)；承重事实（K）操作细则见 [assets/k-facts.md](assets/k-facts.md)。
